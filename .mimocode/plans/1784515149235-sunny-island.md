# ILM Hunt — Comprehensive Fix Plan

## Context

Another system audited the ILM Hunt app and flagged issues across bugs, design consistency, i18n, content, and admin panel. This plan addresses all findings systematically with thorough, well-tested fixes (no deadline pressure).

### 1D. Fix Lifeline/Power-Up Coin Deduction (Client-Only)

All lifeline and power-up coin costs are deducted client-side only. The server never validates or deducts coins for usage. This affects:
- Lifelines: 50/50 (50 coins), Ask Imam (75 coins), Skip (100 coins), Extra Time (100 coins), Reveal Answer (200 coins)
- Power-ups: Double Points (100 coins), Streak Shield (150 coins), XP Boost (200 coins), Free Pass (300 coins), Category XP Boost (250 coins)

**Files to modify:**
- `src/app/(app)/quiz/actions.ts` — Add `lifelineUsed?: string` to `SubmitOptions`, validate and deduct coins server-side
- `src/components/game/QuizView.tsx` — Pass `lifelineUsed` identifier to server action instead of deducting locally

**What to change:**
```ts
// actions.ts — SubmitOptions
interface SubmitOptions {
  usedHint?: boolean;
  responseTimeMs?: number;
  doublePoints?: boolean;
  lifelineUsed?: string; // '50-50', 'ask-imam', 'skip', 'extra-time', 'reveal-answer'
}

// actions.ts — Before grading, check and deduct coins
if (opts.lifelineUsed) {
  const cost = LIFELINE_COSTS[opts.lifelineUsed]; // Define cost map
  if (profile.coins < cost) throw new Error('Insufficient coins');
  const { error } = await supabase
    .from('profiles')
    .update({ coins: profile.coins - cost })
    .eq('id', user.id);
  if (error) throw error;
}
```

**Note:** This is lower priority than the other bugs since it only affects coin balance (not quiz scoring), but should be fixed for consistency. Without this fix, users can use unlimited lifelines for free by manipulating client state.

## Execution Order

1. **Phase 1A** (2× Points lifeline) — Critical user-facing bug, fast fix
2. **Phase 1B** (Quiz page crash) — Critical runtime crash, fast fix
3. **Phase 1C** (Multiplayer migration + security) — Critical feature broken + security issue
4. **Phase 1D** (Lifeline coin deduction) — Lower priority but related to 1A
5. **Phase 2A** (Design tokens) — Affects visual consistency across 15+ components
6. **Phase 2B** (Category taxonomy) — Can be done in parallel with 2A
7. **Phase 3A** (Admin panel) — Independent, can start after Phase 1
8. **Phase 3B** (i18n documentation) — Low effort, can be done anytime
9. **Phase 4A** (Content seeding) — Depends on Phase 1C (multiplayer migration) being done
10. **Phase 4B** (Dead code cleanup) — Do last, after all other changes are verified

## Key Risks

1. **Multiplayer RLS fix** — Changing from `using (true)` to participant-based checks could break the Realtime subscription logic if the subscription relies on seeing all room data. Need to verify Realtime still works with restrictive RLS.
2. **Category taxonomy unification** — The DB categories table might have different slugs than the hardcoded IDs. Need to verify or create a mapping.
3. **Admin panel wiring** — Converting from mock to live data means the admin panel will show empty/zero stats until real content exists. This is correct behavior but may look broken initially.
4. **Quiz page conversion** — Converting from Client to Server Component requires splitting the page into two components. Need to carefully separate server-fetched data from client-side state management.
